## 事件原因

发现一块16Ti的固态硬盘损坏了，需要在ceph中进行移除

## 解决思路

1. 通过准备事项进行安全移除前验证
2. 清除ceph侧和rook侧的配置
3. nvme2n1
## 准备事项

| 检查项 | 命令 | 预期结果 |
| --- | --- | --- |
| OSD 已 out | `ceph osd tree \| grep osd.0` | `down/out` |
| 可安全销毁 | `ceph osd safe-to-destroy osd.0` | `safe-to-destroy` |
| 集群状态 | `ceph -s` | `HEALTH_OK` 或 `HEALTH_WARN`（仅因 osd.0 down） |
| 确认 hostPath 归属 | `cat /var/lib/rook/rook-ceph/<fsid>_<osd-fsid>/whoami` | 输出 `0` |
| 确认对应物理盘 | `lsblk -f` /` ceph osd metadata osd.0` | 定位到 `/dev/nvmeXn1` |

## 处理过程

```Bash
# 开启保护
ceph osd set noout
ceph osd set norebalance
ceph osd set nobackfill

## 限速（NVMe 可调低 sleep，减少业务影响）
ceph config set osd osd_max_backfills 1
ceph config set osd osd_recovery_max_active 1
ceph config set osd osd_recovery_sleep_ssd 0

# ceph 侧清理
ceph osd purge 0 --yes-i-really-mean-it

## 清理验证
ceph osd tree | grep osd.0
ceph auth ls | grep osd.0

# rook 侧

## 备份 cephcluster
kubectl -n rook-ceph get cephcluster -o yaml \
  > /tmp/cephcluster-store-prod-$(date +%Y%m%d-%H%M%S).yaml

## 删除 cephcluster 中的对应硬盘

## 正常情况下，Rook 在显式模式下，检测到 CR 中设备被移除后，会自动删除对应的 OSD Deployment。 等待 1-2 分钟。如果无法自动清理，可以手动删除 osd.0 的 deployment

# 节点侧清理（ceph-store-01）
## 1. 确认 hostPath 归属（必须输出 0，也就是osd.id）
cat /var/lib/rook/rook-ceph/5a1b2c3d-0000-4000-8000-000000000000_11111111-2222-3333-4444-555555555555/whoami

## 2. 删目录
rm -rf /var/lib/rook/rook-ceph/5a1b2c3d-0000-4000-8000-000000000000_11111111-2222-3333-4444-555555555555

# 解除保护
ceph osd unset noout
ceph osd unset norebalance
ceph osd unset nobackfill

## 如果有
ceph config rm osd osd_max_backfills
ceph config rm osd osd_recovery_max_active
```
