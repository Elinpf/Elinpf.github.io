## DeepSeek给出来的方向

研究 Kubernetes 集群底层逻辑是一个深度实践的过程，以下是系统化的学习路径和实践方法：

### 一、底层研究核心路径

1. **核心组件拆解**
   - **etcd**：集群大脑
     ```Bash
     # 查看 etcd 数据
     ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
       --cacert=/etc/kubernetes/pki/etcd/ca.crt \
       --cert=/etc/kubernetes/pki/etcd/server.crt \
       --key=/etc/kubernetes/pki/etcd/server.key \
       get / --prefix --keys-only
     ```
   - **kube-apiserver**：请求入口
     ```Bash
     # 查看 API 请求日志
     journalctl -u kube-apiserver -f --output=cat | grep -v healthz
     ```
   - **kubelet**：节点代理
     ```Bash
     # 查看节点事件
     kubectl describe node <node-name> | grep -A 20 Events
     ```
2. **网络实现深度分析**
   ```Bash
   # 追踪 Pod 通信路径
   kubectl exec -it <pod> -- tcpdump -i any -nn host <target-ip>
   # 查看 Calico 路由表
   calicoctl get workloadEndpoints -o wide
   # 检查 iptables 规则链
   iptables-save | grep KUBE-SVC
   ```
3. **存储机制解剖**
   ```Bash
   # 查看 OpenEBS 卷拓扑
   kubectl get cstorvolumes -n openebs -o yaml
   # 追踪 PV 挂载链路
   lsblk -f | grep <volume-id>
   ```
### 二、实践研究方法论

1. **动态观测技术**
   ```Bash
   # 实时监听资源变化
   kubectl get pods --watch -A
   # 观测 etcd 租约机制
   ETCDCTL_API=3 etcdctl lease list
   ```
2. **故障注入实验**
   ```Bash
   # 模拟网络分区
   iptables -A INPUT -p tcp --dport 6443 -j DROP
   # 杀死关键进程
   pkill -9 kube-controller
   # 磁盘压力测试
   fio --name=pressure --ioengine=libaio --rw=randwrite --bs=4k --numjobs=16 --size=1G --runtime=60
   ```
3. **源码级调试**
   ```Go
   // 示例：调试 kube-scheduler
   func main() {
       // 设置高日志级别
       klog.InitFlags(nil)
       flag.Set("v", "5")
    
       // 核心调度逻辑
       scheduleOne() {
           klog.Info("开始调度周期")
           pod := nextPod()
           klog.Infof("处理 Pod: %s", pod.Name)
       }
   }
   ```

   编译调试：

   ```Bash
   # 构建调试版本
   make kube-scheduler GOFLAGS="-gcflags='all=-N -l'"
   # 使用 delve 调试
   dlv exec ./_output/bin/kube-scheduler -- --kubeconfig=/etc/kubernetes/scheduler.conf
   ```
### 三、关键研究方向

1. **控制循环机制**
   - 使用控制器模式验证：
     ```Bash
     # 观察 Deployment 状态流转
     kubectl get deployment -w -o jsonpath='{.status.conditions}'
     ```
   - 自定义控制器开发（示例 repo：kubernetes/sample-controller）
2. **CRD 扩展原理**
   ```Bash
   # 查看 CRD 注册过程
   kubectl get --raw /apis/apiextensions.k8s.io/v1/customresourcedefinitions
   # 跟踪 API 请求
   kubectl proxy &
   curl http://localhost:8001/api/v1/namespaces/default/pods?watch=true
   ```
3. **调度器算法**
   ```Bash
   # 查看调度决策日志
   kubectl logs -n kube-system <scheduler-pod> | grep -i scoring
   # 生成调度描述
   kubectl get pods <pod> -o jsonpath='{.status.conditions[?(@.type=="PodScheduled")].message}'
   ```
### 四、进阶工具链

| 工具 | 用途 | 示例 |  |
| --- | --- | --- | --- |
| **ebpf** | 内核级追踪 | `bpftrace -e 'tracepoint:syscalls:sys_enter_* { @[comm] = count(); }'` |  |
| **systemtap** | 深度性能分析 | `stap -e 'probe process("kubelet").function("*") { println(pp()) }'` |  |
| **crictl** | CRI 层调试 | `crictl inspect <container-id> | jq .info.runtimeSpec` |
| **kubectl-debug** | 节点诊断 | `kubectl debug node/<node> -it --image=nicolaka/netshoot` |  |

### 六、实践路线图

1. **基础层**：通过`kubectl describe`/`get -o yaml`理解资源状态机
2. **组件层**：使用`journalctl`分析组件日志，理解控制循环
3. **网络层**：通过`tcpdump`+`iptables`跟踪数据流
4. **存储层**：结合`lsof`+`strace`分析卷挂载
5. **调度层**：修改调度器源码添加自定义指标
6. **内核层**：使用ebpf追踪系统调用
> **关键建议**：从实际问题出发（如"Pod为什么卡在Pending状态?"），沿请求路径逐层深入：
> kubectl → apiserver → etcd → scheduler → kubelet → CRI → 内核系统调用

通过这种"自顶向下拆解+自底向上验证"的方式，配合源码调试和故障注入，能快速建立对K8S底层的系统性认知。
