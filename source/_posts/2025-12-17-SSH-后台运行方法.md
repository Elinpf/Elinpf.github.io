## 使用screen

在最开始就要使用

```Markdown
`screen` 是 Linux 下功能强大的**终端复用器**，可以让你在单个 SSH 会话中创建多个虚拟终端，并且它们会在后台持续运行，即使断开连接也不会中断。

## 核心概念
- **Session**：一个 screen 实例，包含多个窗口
- **Window**：独立的虚拟终端
- **Detach**：临时离开 session（任务继续在后台运行）
- **Reattach**：重新连接到 session

---

### 1. 创建新会话
```bash
screen -S download  # 创建名为"download"的会话
```

### 2. 在会话中运行命令
现在你可以正常执行任何命令：
```bash
pip3 install torch
# 或者
wget http://large-file.zip
```

### 3. 脱离会话（任务继续在后台）
按快捷键：
```bash
Ctrl + A，然后按 D
```
会显示：`[detached from 12345.download]`

### 4. 重新连接会话
```bash
screen -r download  # 通过名称连接
# 或
screen -r 12345     # 通过ID连接
```

---

### 会话管理
| 命令 | 作用 |
|------|------|
| `screen -S <name>` | 创建指定名称的会话 |
| `screen -ls` | 查看所有会话 |
| `screen -r <name>` | 重新连接会话 |
| `screen -x <name>` | 共享会话（多人同时操作） |
| `screen -R <name>` | 连接或创建会话（如果不存在） |

### 在会话内操作
| 快捷键 | 作用 |
|--------|------|
| `Ctrl+A D` | **脱离**当前会话（最常用） |
| `Ctrl+A C` | **创建**新窗口 |
| `Ctrl+A N` / `P` | 切换到**下一个/上一个**窗口 |
| `Ctrl+A "` | 显示所有窗口列表（可切换） |
| `Ctrl+A A` | 切换到最近使用的窗口 |
| `Ctrl+A K` | **关闭**当前窗口 |
| `Ctrl+A \` | **终止**整个会话 |

## 实战示例：后台下载大文件

```bash
# 1. 创建会话
screen -S mydownload

# 2. 执行下载
wget http://example.com/large-file.zip

# 5. 第二天重新SSH登录，查看进度
screen -r mydownload

# 6. 完成后退出会话
exit  # 在会话内执行exit
# 或
Ctrl+D  # 快捷键
```

---

### 查看所有会话
```bash
screen -ls
```
输出示例：
```
There are screens on:
    12345.download  (Detached)
    67890.compile   (Attached)
2 Sockets in /run/screen/S-root.
```

### 强制断开并重新连接
如果会话显示 `(Attached)` 但无法连接：
```bash
screen -D -r download  # 先断开别人，再自己连接
```

### 窗口分裂（分屏）
```bash
Ctrl+A S  # 水平分裂
Ctrl+A |  # 垂直分裂
Ctrl+A Tab  # 在分屏间切换
```

### 滚动查看历史输出
```bash
Ctrl+A [  # 进入复制模式
# 按 Esc 退出
```

### 设置状态栏（可选）
在 `~/.screenrc` 文件中添加：
```bash
hardstatus alwayslastline "%{= kw}%-w%{= BW}%n %t%{-}%+w %-= @%H - %LD %d %LM - %c"
```
这样底部会显示窗口列表和时间。

## 常见问题

**问题1**：`Cannot open your terminal '/dev/pts/0'`
```
# 解决方案
script /dev/null
screen -r download
```

**问题2**：会话不见了？
```bash
# 检查是否还在运行
ps aux | grep screen
# 可能被杀死了（OOM），检查系统日志
```

**问题3**：如何让 screen 会话在服务器重启后自动恢复？
```
# screen 本身不支持，但可以用 systemd + tmux/resurrect（更复杂）
```

## Screen vs Tmux 对比

| 特性 | Screen | Tmux |
|------|--------|------|
| 学习曲线 | 简单直接 | 稍复杂但功能更强 |
| 窗口切换 | 基本 | 更灵活（窗格、标签） |
| 配置 | 简单 | 高度可定制 |
| 社区 | 传统 | 活跃 |

**建议**：对于简单需求用 `screen`，长期重度使用可尝试 `tmux`。

现在你可以从容地在任何耗时任务中使用 `screen` 了！
